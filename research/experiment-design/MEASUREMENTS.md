# Measurement and analysis contract — DRAFT

## Raw records and accounting

Each immutable run manifest contains source and dependency hashes, complete config, RNG seeds and scheduled trace hash; host CPU model/ISA/physical and logical cores/RAM/OS/kernel; native versus VM/emulation chain; Docker/image config and manifest digests; observed java -version/JVM flags/GC/heap; effective cgroup CPU/memory and affinity; carrier/event-loop/platform-worker settings; observed DB version/config; monotonic-clock units; wall-clock start/end; command argv/exit/stdout/stderr; instrumentation settings and output hashes. Registry-declared versions are metadata until observed. Never put personal credentials in a shareable manifest.

One record for **every scheduled request**, including those never dispatched: request/class/seed IDs; scheduled arrival, actual send and service receipt; admission decision/limit; executor enqueue/start; pool enqueue/acquire; query start/end; resource release; client terminal time and outcome; exact error/cancel reason and terminal owner; deadline; successful value/result checksum. Record unavailable boundaries as unavailable, never invent timestamps or negative-duration corrections. Cross-machine clocks cannot define one-way latency without measured synchronization bounds; end-to-end is client monotonic, internal spans server monotonic.

Disjoint terminal classes: success-before-deadline, success-late, admission-reject, queue-reject, timeout, cancelled, error, generator-missed and unresolved-at-cutoff. Terminal ownership prevents double counting; late DB work after a client timeout is a separate lifecycle record linked to the same ID. At each cutoff scheduled = terminal classes + unresolved. Dispatched = received + in-transit/unconfirmed, with reconciled IDs. Admitted = completed/cancelled/failed terminal server work + still-active server work. Acquires − releases = held resources, not client requests. At final drain admission leases, pool connections and active server operations must reconcile to zero or explicitly retained unresolved IDs. Record duplicate callbacks and rejects after terminal as errors.

### Proposed pool-queue endpoint population

Primary endpoint is **restricted queue residence among requests entering the pool queue**, replacing the previous undefined acquisition-only mean before freeze. Proposed restriction horizon τ=100 ms from pool enqueue is fixed across arms (distinct from the client deadline measured from scheduled arrival). Residence ends at acquisition or actual terminal queue departure by abandonment/cancellation/error; record which occurred. A client timeout is not queue departure if server work remains queued. For each entrant use min(actual queue-departure/acquisition time − enqueue time, τ). Entrants still queued through τ contribute τ as observed restricted residence, not an invented acquisition time. If observation ends before τ without queue departure, retain the observed lower bound and upper bound τ; publish run-mean bounds and suppress point-estimate D/H1 confirmation until the frozen censoring rule supports the endpoint. Do not assume noninformative censoring or silently drop unresolved entrants.

Compute each run's arithmetic mean over all entrants, then transform with the 1 ms offset for paired D. A zero-entry run has an undefined conditional mean/D, not zero wait; report it and block that confirmatory contrast. Non-entry requests receive no queue residence or fictitious acquisition time. Report entry fraction among all scheduled requests, acquisition probability among entrants, all departure types and unrestricted acquisition-wait distributions with their competing outcomes. Entry is treatment-dependent; this conditional contrast alone is not an all-offered causal effect. All-scheduled goodput, outcome risks and resource accounting remain unconditional companion endpoints. The endpoint/horizon remain DRAFT pending approval and must be frozen before data.

Time series (100 ms proposed) record queue lengths/occupancy, admissions/rejections, current limits and exact control-law inputs/updates, DB active queries/locks and CPU, process/container CPU throttling and memory, allocation/GC pauses, runnable threads/carriers, pool creation/destruction, generator lag. Retain JFR with event availability/config, stacks and workload markers; absence of pinning events alone does not prove no pinning. Record instrumentation loss/drop counters.

## Offered load and tails

Generate arrivals independently of completions; do not pace new requests by response. Precompute Poisson arrival and demand schedules and replay identical schedules within a paired block. Bound client outstanding resources for safety without silently blocking the schedule: any missed dispatch retains its scheduled ID and generator-missed outcome. Primary goodput = successful correct responses within 100 ms of **scheduled arrival**, divided by measured wall time. Report actual-send latency as secondary with generator-lag distribution. The baseline capacity estimate is independently calibrated, frozen, and identical across mode comparisons; show absolute offered/admitted/completed/goodput rates.

Report p50/p95/p99/p99.9 and ECDF/CCDF of successful-response latency conditional on success, separately from time to any terminal disposition and time to successful completion among **all offered requests**. These populations are not interchangeable. Conditional successful percentiles cannot alone rank controllers that reject work. For the all-offered successful-completion distribution, permanent non-success contributes mass at +∞ (rejection, permanent cancellation/error, generator-missed non-dispatch); unresolved work retains its censoring time and possible eventual outcome. Do not assign zero or a timeout threshold as successful completion. An all-offered quantile is finite only when supported by the success cumulative mass under that definition; otherwise report infinite when established by permanent noncompletion, bounds when supported by censoring information, or not estimable. The unresolved fraction alone, including a 1% cutoff, is not an identification rule. Preserve all outcome proportions and raw censoring/cutoff times; no unqualified noninformative-censoring assumption. The time-to-terminal metric uses observed terminal dispositions and its own truncation/censoring labels.

Minimum 100,000 successful requests **pooled within a declared cell across independent blocks** is a proposed descriptive p99.9 reporting floor, not a precision guarantee; below it suppress inferential p99.9 and retain descriptive counts. Label pooled percentiles as mixture summaries and also report run-level tails/counts. Roughly 100 observations above p99.9 at that count is arithmetic, not independent replication or assured interval precision. Uncertainty respects complete blocks. Do not extend individual runs until favorable precision emerges; amend future independent runs prospectively.

## Uncertainty and decisions

Experimental unit is an independent run/block, not individual requests. Publish each run and paired contrast. Estimate 95% paired cluster-bootstrap CIs with 10,000 block resamples and a frozen seed; resample complete paired vectors spanning primary modes/pools/demand distributions, preserve mode/controller/JDK pairing and within-run autocorrelation. Ten blocks remain ten independent units regardless of resample count; marginal interval validity/precision needs a separate pilot assessment before freeze, and pilot data cannot also be confirmatory data. Use hierarchical host/day resampling only with enough independent host/day clusters; one-host inference remains conditional on that host. For within-run time-series uncertainty use a prespecified 5 s moving-block sensitivity and report 1/10 s alternatives; do not call these independent replications.

Primary family comprises H1 on JDK25 under the two specified demand distributions. The authoritative proposed Bonferroni decision uses two 97.5% two-sided marginal CIs: confirm only if both lie wholly above +log(1.10), or both wholly below −log(1.10); either common direction is permitted. Valid marginal coverage would imply at least 95% family coverage, but bootstrap coverage is not established by this proposal. Holm tests (family α=.05), if retained, are secondary and cannot override the interval rule. H2 requires this rule on monitor-free JDK25; direct JDK differences need paired interaction uncertainty, not two separate significance decisions. Ordinary 95% intervals elsewhere are descriptive unless explicitly included in a later frozen family. Equivalence requires a CI contained in the prespecified band; failure to reject zero is not equivalence. Wide intervals mean inconclusive. Model predictive uncertainty must include outer calibration resampling with each refit shared across affected cells, separate from inner confirmatory-block resampling. Freeze and validate that hierarchy before execution; do not add calibration noise to D where identical mode-blind predictions cancel. Report standardized and absolute effects as well as ratios.

Define overload operationally without claiming an asymptotic instability: over ≥30 s, positive outstanding-work slope plus deadline misses >1%, or persistent resource-cap rejection. Define recovery after the downshift as three consecutive 10 s bins with goodput ≥95% of that arm's pre-shift median and deadline-miss fraction ≤1%; report right-censored if absent before stage end. Report overshoot, queue-area integral and timeouts as secondary metrics. Do not equate overload under offered rate above capacity with collapse; “collapse” additionally requires declining completed throughput under increased offered load with matched capacity, raw resource evidence and uncertainty.

## Run validity and preservation

Proposed validity exclusions, frozen before confirmation: source/hash mismatch; wrong ISA/emulation for performance; wrong result/accounting invariant; DB crash; trace not replayed; generator-missed fraction >0.1%; or p99 dispatch lag >1 ms. Publish every excluded run, reason and its metrics; these exclusions cannot silently discard an overloaded server's bad results. Distinguish generator failure from server backpressure. Run one new matched block for a technical invalidation, retain the original, cap replacements at two per cell and otherwise mark cell incomplete. Valid poor outcomes/timeouts/OOM caused by the tested policy are outcomes, not exclusions. Emergency caps terminate unsafe resource exhaustion and count all unfinished work; log the cap and avoid claims beyond it.

Raw requests, traces, JFR, environment manifest, command logs, all tuning data, failures and analysis outputs require a content-hash index. Bind failed/excluded runs and preflight outputs to source/config hashes and terminal status too; an unattempted phase retains the available manifest and missing-evidence reason rather than a fabricated execution record. Derived tables name exact inputs, exclusions and script version. Freeze independent expected invariants/decisions before executing any new implementation oracle. Keep an amendment ledger with date, reason and untouched earlier definitions; no retrospective preregistration.
