# Proposed preregistration — DRAFT, not frozen

## Questions, estimands and rejection rules

| Question / proposed hypothesis | Established explanation to exclude | Operational test | Falsifier / permitted conclusion |
|---|---|---|---|
| RQ1: Does VT execution have a material finite-pool interaction beyond ordinary queueing? H1: held-out residual pool-wait inflation differs between VT and matched platform execution. | Finite-server saturation, arrival burstiness, service variance, admission selection, CPU/database bottlenecks and pool sizing. | Fit mode-blind queueing nulls on independent calibration; compare paired low/high-pool residual contrasts at identical offered arrivals, request classes and capacity. Primary endpoint is log mean pool wait with a 1 ms offset. | No residual outside the prespecified equivalence band, or richer conventional null predicts it: reject a novel runtime mechanism. Imprecision means inconclusive, not evidence of novelty. |
| RQ2: Is any residual independent of removed monitor pinning? H2: same-direction material H1 remains on JDK25 and in monitor-free code. | JDK21 monitor pinning, JNI/foreign frames, scheduler/carrier limits and framework integration. | JDK21 versus JDK25 primary; separately pinned JDK24 replication only if validated. JFR plus monitor/native/foreign isolation and carrier interventions. | Disappearance after JEP491 or after matched modes/pinning removal narrows to a known runtime/version mechanism. Do not infer all native/foreign behavior from a JNI fixture. |
| RQ3: Would a future mechanism-based controller add value beyond established limits? H3, conditional and not authorization to implement: SLO-goodput improves at equal constraints under held-out capacity/load shifts. | Fixed/pool controls, generic credit/delay/gradient feedback and unequal tuning budgets. | Paired trials against fixed, pool-only, Breakwater-inspired, official Gradient2 and explicitly scoped Envoy-style controls; common SLO, bounds, telemetry and training budget. | Any mandatory comparator equivalent within 5% relative goodput and 10% recovery-time margins, target mismatch, or tuning-only gains rejects broad added-value claim. Unsupported comparators block that claim. |

Primary RQ1 comparison is VT JDBC versus platform JDBC. Reactive R2DBC is a required triangulation control, not pure thread-mode substitution: driver, event-loop and pool implementations differ. Test it separately and disclose those differences. Neither H1 nor H2 alone establishes a new controller or broad novelty.

Proposed practical band for H1 is ±log(1.10) on the difference-in-differences of log(mean wait + 1 ms). Define residual r = observed log(mean wait + 1 ms) minus predicted log(mean wait + 1 ms). At each paired block, D = (r_VT,small − r_PT,small) − (r_VT,large − r_PT,large), with pool small=2 and large=16. Primary load is 1.0 times calibration capacity for each pool, common across modes; absolute arrivals are identical within pool/mode pairs. H1 requires a simultaneous 95% CI wholly outside the practical band on JDK25, same-direction replication under a second service distribution, and failure of the conventional model alternatives below. JDK21 alone cannot satisfy H2. These are proposed decision rules; freeze before confirmatory data.

Pool size is randomized treatment. Realized occupancy is a mediator and outcome, not a baseline confounder to condition away. Report mode × assigned-pool interaction first; mode × realized-occupancy plots are descriptive. For zero or tiny waits, report absolute differences too; offset sensitivities of 0.1 and 10 ms cannot replace the primary endpoint.

## Queueing null ladder

1. Conservation and capacity: offered rate λ, admitted rate λa, service demand E[S], pool c, utilization estimate ρ=λa E[S]/c. Little's Law applies only with matching population/window and stationarity; do not use offered λ with admitted residence time. A ρ>1 transient is ordinary overload, not discovery.
2. M/M/c provides a transparent stationary sanity check only for the exponential/Poisson calibration case. Predictions diverge as ρ approaches one; finite queues, rejection and deadlines must not be silently treated as infinite equilibrium queues.
3. Main null: finite-capacity GI/G/c discrete-event model with the exact offered schedule, empirical calibration service distributions, admission rules, deadlines, queue bound and abandonments. Do not feed observed overloaded completion times back as exogenous service demand. Fit only low-load/server-side calibration data and predict held-out pool/load cells with prediction intervals.
4. Stronger conventional null: tandem application-worker, pool, database and CPU queues with measured service-demand classes, contention-dependent DB demand and class routing calibrated independently. Include platform executor capacity, event-loop dispatch, network overhead and timeout cleanup. Select model structure before confirmation using calibration predictive error; report all nulls rather than choosing the weakest.

Assess time-binned occupancy, wait distributions, rejection, throughput and recovery jointly. Validate simulator conservation and analytical special cases before using predictions; oracle expected values must be frozen before implementation outputs. A residual may expose misspecification or driver overhead. A mechanism claim requires targeted intervention changing the proposed causal pathway while preserving the workload, and successful independent prediction. Without that, use “unexplained residual,” not “VT-specific instability.”

## Matched workload and matrix

Single service → finite pool → isolated PostgreSQL initially; no cascade claim from one downstream hop. Same generated request IDs, query text/parameters, prepared-statement policy, row cardinality, transaction isolation (READ COMMITTED), autocommit, result consumption, timeout origin and cancellation semantics across modes. Match pool min/max, prewarming, connection lifetime, validation and retry policy. Disable automatic retries in the primary experiment. Use genuine nonblocking R2DBC; no blocking database call on reactive event loops. Record runnable workers/carriers separately from admission and connection limits.

| Factor | Proposed primary levels | Extension / limitation |
|---|---|---|
| JDK | pinned 21 and 25 observed native builds | 24 requires separately pinned/validated build; do not label 25 results “24 measured” |
| Execution | platform JDBC, VT JDBC, reactive R2DBC | same minimal harness semantics; framework integration is a separate replication |
| Pool | 2, 8, 16 | 2 vs16 primary contrast; 8 checks shape |
| Demand | deterministic 10 ms; lognormal mean10 ms CV2 via fixed per-request schedule | calibration validates actual DB-side demand; mixed query classes and real SQL replication later |
| Offered load | 0.5, 0.8, 1.0, 1.2, 1.5 × independently calibrated pool capacity | capacity per pool/demand fixed across modes; also publish absolute rates |
| Arrival process | seeded Poisson, open loop | deterministic paced and burst on/off sensitivities, same mean rate |
| Limits | pool-only; fixed {c,2c,4c}; Breakwater-inspired; official Gradient2; reduced Envoy-style | no-admission path has bounded emergency resource cap, reported explicitly; fixed chosen on calibration only |
| Shifts | load 0.8→1.2→0.8; demand mean10→20→10 ms | stages 60/120/120 s after warmup; capacity reduction is separate intervention |

Synthetic DB delay is a controlled waiting workload, not representative SQL CPU/locking behavior. Validate actual achieved demand; a future real-query workload must use identical results and plans across modes and be preregistered separately. Primary RQ1 uses pool-only with identical emergency cap; controller comparison is a later phase so adaptive selection cannot masquerade as an execution-mode effect.

## Controller fairness

Preserve all reduced validation evidence. Breakwater-inspired is reduced/paper-derived, not the author artifact. Use official pinned Gradient2 core as primary; reduced Gradient2 is diagnostic only. Envoy-style means the documented reduced law unless official proxy integration and its trace/window/probe behavior independently pass. Do not promote five gradient equation fixtures to full Envoy equivalence. An official Envoy deployment changes topology; add the same proxy path/overhead to every arm and separately account its minRTT probes.

Every tunable controller receives the same maximum of 12 prespecified configurations × 3 calibration seeds, same training traces and wall-time cap. Defaults are included. Freeze the exact configuration list before calibration; unused budget is not transferred. Fixed-limit search uses the same training information and explicitly counts its trials. Use a common SLO of 100 ms from scheduled arrival, common admission bounds [1,64], maximum queued/inflight safety budget, no retries, common rejection/timeout ownership, and identical accessible measurements. If valid calibration shows the SLO infeasible, revise the draft and restart calibration before freeze. Choose maximum training goodput subject to ≤1% deadline failures among admitted work; ties within 1% prefer simpler/default configuration. Preserve rejected candidates and all tuning outcomes. No per-test-load hindsight retuning. Controller-specific clocks/sample windows are documented rather than forcibly equated into a different algorithm.

Do not implement a candidate until baseline gate and independently approved design permit it. Candidate evaluation, if later justified, receives the same budget, seeds and observability. Expanded Protego/Bouncer/TopFull comparisons remain requirements for claims against those systems; the current limited topology and validated set cannot support “beats prior overload control” generally.

## Repeats, timing and causal checks

Propose 10 independent paired blocks for each confirmatory cell; independent process/DB reset and unique arrival seeds per block. Share each block's immutable arrival/demand trace across modes/controllers, not process state. Randomize run order within JDK/pool/day blocks with a published seed; balance order with a Latin schedule. Preserve carryover diagnostics, restart and prewarm uniformly. Fixed 60 s warmup, 180 s measurement and up to 30 s drain for steady cells; shifted cells follow the table. Primary analysis excludes warmup only by this fixed rule. Pilot variance may inform a prospective precision calculation and sample-size amendment before freeze; no optional stopping on significance. If resources cannot deliver the frozen count, mark incomplete and report precision, not a powered claim.

Preregister ablations: monitor-free versus monitor-held waiting; separate JNI and foreign-call fixtures if validated; carrier parallelism {1,2,4} within allocated cores; platform-worker sizes {c,4c,64} as resource/worker-cap sensitivity; reactive event-loop size; generous versus tight heap; JFR on/off; pool-wait deadlines; no retry versus fixed bounded retry sensitivity; demand tails and burstiness; DB capacity fixed versus deliberately shifted. Do not sweep all factors indiscriminately: RQ1 core first, then mechanism interventions on preregistered cells, then any controller study. Adjusting carriers after seeing an advantage is exploratory.

Primary threat checks: generator scheduling misses/coordinated omission, timeouts/selective completion, noisy neighbors/thermal throttling, CPU affinity/NUMA, JIT/GC warmup, network/DB contention, driver/framework inequivalence, pooled-connection settings, controller window/probe semantics and multiple comparisons. Second native host/database/framework are replication scope, not silently assumed generality. Emulation, a container's architecture string and registry metadata cannot establish native performance provenance.
