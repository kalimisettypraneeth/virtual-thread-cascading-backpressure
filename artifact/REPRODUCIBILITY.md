# Reproducibility Contract

Record source revision, OS/kernel, CPU model, memory, container runtime, JDK version, dependency versions, workload configuration, experiment duration, warmup, repetition count, random seed when applicable, raw telemetry, and processing commands.

Raw experimental outputs must not be hand-edited. Derived data and figures must be regenerated by committed scripts.

No benchmark result belongs in the paper unless its provenance can be traced to a committed configuration and raw output.

## Isolated baseline validation

From repository root run `python3 artifact/scripts/validate_baselines.py /tmp/vt-native-validation`. The validator invokes `java --source 17 artifact/baselines/NativeControls.java` using an absolute source path, records raw output and tool/runtime metadata, and hashes both source and validator. Python standard library and a Java runtime containing `jdk.compiler` are required; no services or downloads are used. The committed evidence is in `artifact/results/baseline-validation/java17-native/validation.json`.

The ten checks are correctness-only evidence for two native limiting contracts on the recorded Java 17 build. They are not timing measurements, stress tests, a JDBC harness, virtual-thread tests, or a reactive-framework comparison. CompletionStage plumbing is labeled separately. Reproduction must compare source hashes and test assertions, not volatile timestamps, process paths, or free-memory snapshots.

Source revision pins do not freeze dynamic build dependencies. External baselines require resolved artifact versions and checksums, build/smoke output, independent expected decision traces, and a recorded workload interface. Never certify a reimplementation by using its own output as its expected oracle.
